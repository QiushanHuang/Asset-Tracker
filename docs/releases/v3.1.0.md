# Asset Tracker v3.1.0

Asset Tracker v3.1.0 is the first formal release of the native durable-storage path.

## Highlights

- Saves now produce an exact native durability receipt instead of relying on an unverified atomic path write.
- The primary book can recover across interrupted writes without guessing or silently resetting user data.
- Version snapshots support deduplication, bounded retention, crash recovery, and independent health reporting.
- The macOS bridge exposes strict save, snapshot, load, error, and terminal response shapes.
- Critical pre/post-rename states and two-writer source conflicts are exercised by a real-process fault harness.

## Included assets

- `AssetTracker-v3.1.0-macos-unsigned.zip`
- `AssetTracker-v3.1.0-macos-unsigned.zip.sha256`

The zip contains `AssetTracker.app`. It contains no personal ledger data.

## Installation

1. Download and unzip the macOS archive.
2. Move `AssetTracker.app` to Applications if desired.
3. Open it. Because this build is unsigned and not notarized, macOS may require right-clicking the app and choosing **Open**.

Apple signing, notarization, and Gatekeeper validation were intentionally not performed for this release.

## Data and compatibility

The native ledger remains local at:

```text
~/Library/Application Support/com.qiushan.AssetTracker/AssetTrackerBook.json
```

Before replacing or importing a book, keep an exported copy. The application does not include cloud sync or multi-device conflict resolution.

## Known limitations

- The macOS build is unsigned and not notarized.
- The fault harness covers the critical release paths, not the full fault-point × role Cartesian matrix.
- A legacy browser backup compatibility path remains; the native `storage.save` and `storage.snapshot` routes use durable storage.
