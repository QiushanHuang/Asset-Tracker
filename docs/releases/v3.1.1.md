# Asset Tracker v3.1.1

Asset Tracker v3.1.1 is a production hotfix for the v3.1.0 native durable-storage release.

## User-visible fix

- Opening an existing ledger with automatic backup enabled no longer enters `账本已进入保存保护模式` with `保存结果未知` before a save is attempted.
- The normal ledger interface remains writable after startup and navigation/buttons respond normally.
- Startup auto-backup now reaches the strict native `storage.save` route and returns a verified durable receipt.

## Root causes fixed

1. **WebKit timer receiver mismatch**
   The save queue copied `Window.setTimeout` and `Window.clearTimeout` onto a plain object. WebKit rejects those methods unless their receiver is a `Window`, so the durability deadline failed before native storage I/O and the queue conservatively classified the result as unknown. The queue clock now invokes captured timer functions with the real `window` receiver.

2. **WKScriptMessage numeric bridge ambiguity**
   JavaScript numeric `1` arrives through WKScriptMessage as `NSNumber`. The strict parser's generic Boolean check treated that value as `true`, rejecting the valid `schemaVersion: 1`. Native parsing now distinguishes CFBoolean from numeric NSNumber and still rejects real booleans, fractional values, and non-finite values.

## Functionality included

This patch retains the complete v3.1 native storage feature set:

- exact source/state-bound native durable save receipts;
- crash-safe ordinary ledger recovery and health reporting;
- snapshot creation, deduplication, bounded retention, and recovery;
- strict load/save/snapshot/error/terminal bridge DTOs;
- serialized save coordination and confirmed-source conflict handling;
- critical real-process rename and two-writer CAS fault coverage;
- local JSON/Excel import/export, multi-currency ledger management, analytics, automation, and templates.

## Regression coverage

- A receiver-sensitive browser harness reproduces WebKit timer semantics.
- A native activation-backup test proves one `storage.save` request is dispatched and the application remains writable.
- Swift tests exercise WKScriptMessage-style `NSNumber(1)`/`NSNumber(2)`, CFBoolean rejection, and fractional-number rejection.
- The packaged App was opened against an existing local ledger and displayed `账本已安全打开` and `已安全写入本机`; navigation to Settings was also verified.

## Installation

1. Download and unzip the macOS archive.
2. Replace the previous `AssetTracker.app` with the v3.1.1 app.
3. Open it normally. Existing ledger data remains under Application Support.

This build is intentionally unsigned and not notarized. Apple signing, notarization, and Gatekeeper validation were not performed.

## Local data

The native ledger remains at:

```text
~/Library/Application Support/com.qiushan.AssetTracker/AssetTrackerBook.json
```

The first successful durable save may create the managed `Recovery` namespace beside the primary ledger. That namespace is part of crash recovery and must not be manually edited.
