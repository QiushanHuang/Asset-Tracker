# v3.1.1 completion log

Date: 2026-08-11

Release: `v3.1.1`

Repository: `QiushanHuang/Asset-Tracker`

## Incident

After v3.1.0 opened an existing native ledger, startup auto-backup immediately displayed:

```text
账本已进入保存保护模式
保存结果未知，请重新启动以核对账本；系统不会自动重试。
```

The protection state made the normal application shell inert, so buttons and navigation could not be used.

## Root-cause evidence

- The existing primary ledger was readable, regular, owned by the current user, and unchanged when the failure occurred.
- No storage lock or Recovery namespace was created by the failing launch, proving native durable mutation had not started.
- A live WebKit probe reproduced `TypeError: Can only call Window.setTimeout on instances of Window` before queue adapter I/O.
- After correcting timer dispatch, the request reached the native bridge and returned `无效的 schemaVersion`.
- A focused Swift RED reproduced WKScriptMessage's `NSNumber(value: 1)` being rejected by the Boolean guard.

## Fixes delivered

### Web save queue

- Captured `Window.setTimeout` and `Window.clearTimeout` once during application load.
- Invoked both functions through captured `Reflect.apply` with the real `window` receiver.
- Preserved the existing queue deadline and fail-closed behavior.

### Native bridge

- Changed strict integer parsing to accept only mathematically exact NSNumber integers.
- Distinguished CFBoolean using CoreFoundation type IDs.
- Continued rejecting booleans, fractional values, malformed fields, and unsupported schema versions.

### Regression tests

- Added receiver-sensitive timer support to the VM application harness.
- Added an end-to-end native startup auto-backup test.
- Added WKScriptMessage NSNumber/CFBoolean parser coverage.
